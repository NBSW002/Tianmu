# 架构边界与组件选型

本轮整理保持两个独立后端与 Vue 前端，不额外拆微服务或创建通用 Agent 框架。

## 执行控制与可观测性

`CallControl` 显式携带 deadline、取消信号、任务 Token 预算和外部调用记账回调。主循环、预处理和嵌套视频调用共享运行任务自己的预算对象，不从 OpenTelemetry Context 读取执行权限。构造器拒绝空预算或空回调；两参数构造器用于明确的独立调用，创建自身的无上限预算，不代表可以绕过托管运行中的额度。

TraceUsage 仅观察消耗，Trace 关闭、切换出口或跨线程执行都不改变预算约束。模型 SDK 不能自动执行业务工具或隐式重试收费请求。

## 线程与缓存组件

Spring 管理七个具名 `ThreadPoolTaskExecutor` 和单线程 deadline scheduler。通过 `agent.execution.<lane>.core/max/queue` 配置运行编排、预处理、模型、普通工具、视频、SSE 与终态收尾（termination）容量。各池有界，满载时拒绝，不以调用者线程执行慢任务。

watchdog 到期只调用 RunState.signalTimeout：以原子控制状态撤销后续执行并发出本地取消信号，不获取可能被数据库写入占用的 RunState monitor，不执行终态写库或 AgentHook。之后尝试将收尾交给 terminationExecutor，默认 core=2/max=4/queue=32；池满时不 CallerRuns、不在 timer 上记录同步日志，由现有 agent.executor.rejected 指标和待收敛计数反映积压，并由 RunService 维护入口接续。公开终态与 DONE 仍需持久化确认，因取消醒来的 worker 不能把已生效的 deadline 原因改成 CANCELLED/SHUTDOWN。

仅 watchdog 发起的同步收尾迁入独立池；已有 GATE/TRANSFORM 的顺序与校验语义不变。终态 Hook 也可能由原 worker 或维护入口触发，但不再由 watchdog 执行。慢 Hook/存储仍占用收尾线程，池全部繁忙时公开终态可能延后；本地停止信号不等待该池。CancellationToken 回调仍限定为受信任的快速适配器/Future 取消操作，不能注册业务 Hook、网络查询或其他慢工作；这不是任意第三方代码的强制终止机制。

Micrometer 提供 `executor.*` 指标；`agent.executor.rejected` 记录拒绝次数。托管对象关闭由 Spring 依赖关系管理，直接构造的测试 fixture 只关闭自己创建的池。排队的运行任务、模型/工具调用和预处理分支在取消时移出相应队列，避免已停止任务继续占据容量。

视频内存缓存改用 Caffeine 的最大容量和写后过期策略。在途 Future 的原子登记也使用 Caffeine；保留的自定义逻辑仅包括调用者独立 deadline/取消、预算归属、失败重试条件和全局并发准入。不会给在途项配置可能导致重复执行的容量淘汰或 TTL，也不会另建无界后台执行器。

## 业务与持久化边界

- `core.VideoContent` 是共享事实契约；核心类型不依赖视频模型、JDBC、Spring 或 Trace 实现。
- `ToolDispatcher` 保留工具目录、Schema 与通用能力准入；业务约束和证据检查委托 `BusinessEvidencePolicy`，报告交付委托 `ReportArtifacts`。
- 报告使用 `ReportStore`，会话读取使用 `ConversationStore`，存储管理端点使用 `StorageManagement`。Controller 不再依赖 `MysqlRunRepository` 实现类型。
- `MysqlReportStore` 承接报告元数据、对象写入、READY 更新与失败清理；通过受限协作接口使用原有 run/session 锁和事务 guard。会话与任务的公共数据库锁序不变。
- `RunBackend.commit` 的“持久化终态与事件先提交，再暴露进程内终态”协议保留，不改为异步 Spring 事件。`RunState` 仍是活动任务聚合并保留同步提交边界；没有声称它已经成为完全无副作用的领域对象，也没有新增第二套事务或事件总线。
- 本地停止信号与持久终态分开：取消/失败/超时不等待数据库才通知适配器停止，公开终态和 DONE 仍等待事务成功。RunState 保留单份待提交意图，RunService 复用维护入口进行限批、退避的终态收敛；不重放模型或工具。RunRepository.refresh 仅供内部采纳权威终态，不能作为绕过会话授权的公开读取入口。已清理任务通过 discarded 释放资源，与 committed completion 区分。

业务平台互动服务通过只读 `VideoLookup` 校验视频存在性，关注服务通过用户 Mapper 读取资料，移除相应的服务回环和 `@Lazy`。原互动写入事务与 SQL 行为保持在原有服务中；这次没有迁移消息队列或改变计数一致性策略。

## 标准 Trace 出口

`HARNESS_TRACE_SINK=otlp` 启用 OpenTelemetry SDK 的 OTLP/HTTP exporter 与批处理器；`OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` 默认 `http://127.0.0.1:4318/v1/traces`。Collector 示例位于 `deploy/otel-collector.yaml`，需设置实际 OTLP backend、使用含 file_storage 扩展的发行版，并为队列目录配置持久卷与访问权限。

通用发送队列、重试和持久缓冲由 Collector 处理。示例配置未在用户服务器部署，也未验收远端后端。原 file/kafka 出口继续兼容，以支持离线测试及现有发布环境；切换前需确认 Trace 数据接收和保留策略。审计、私有证据和报告仍由业务数据库/对象存储负责，不能依赖遥测采样或导出成功。

## 模型 SDK 评估结论

暂时保留 JDK HttpClient 和最小供应商适配。重复的响应大小限制已合并到 `BoundedHttpBody`，不为替换 HTTP 类库再引入另一层通用客户端框架。

已检查 Spring AI 1.1.8 的 [DeepSeekChatOptions](https://github.com/spring-projects/spring-ai/blob/v1.1.8/models/spring-ai-deepseek/src/main/java/org/springframework/ai/deepseek/DeepSeekChatOptions.java) 和 [DeepSeekApi](https://github.com/spring-projects/spring-ai/blob/v1.1.8/models/spring-ai-deepseek/src/main/java/org/springframework/ai/deepseek/api/DeepSeekApi.java)：当前选项未提供本项目已使用的 thinking 字段，非流式调用由同步 RestClient 完成，无法直接沿用当前基于 Future 的取消注册方式。引入后还需额外适配请求字段、取消和响应上限，因此本轮不默认迁移。

[Spring AI 2.x](https://docs.spring.io/spring-ai/reference/getting-started.html) 对应 Boot 4.x，本项目仍是 Boot 3.5.4。后续迁移必须先通过现有本地 HTTP 契约测试，包括 thinking 禁用、无隐式重试、usage 缺失、非法 JSON、响应上限、在途取消和错误脱敏；不能把 SDK 名称替换当作维护成本已经下降。

## 前端和架构回归

页面使用 `useAgentRunMonitor` 管理订阅/轮询生命周期，使用 `useAgentHistory` 管理用户隔离的本地索引。纯 `run-monitor.mjs` 用于测试关闭、重放去重、权限错误和旧会话迟到响应。重连等待会在完成或取消时注销 abort listener。

移除未被 ESLint 配置引用且导致 peer 冲突的 `@vue/eslint-config-standard`，支持普通 `npm ci`；未强制升级 Vue CLI 或执行 `npm audit fix --force`。CI 新增前端协议测试和生产构建。ArchUnit 校验核心依赖方向、预算与遥测分离、Controller 与存储实现分离，以及业务互动/关注服务的依赖边界。

## 2026-10-26 后续架构迭代

本轮按任务契约、准备/交付、运行时依赖、存储职责的顺序修改：

- `TaskConditions` 为三类业务任务提供类型化条件视图，继续读写既有 specification JSON。视频播放时间由准备阶段固定，工具执行前和证据登记时校验；按任务生成工具上限，新增工具不会默认获得执行权限。
- `PreparationService` 默认先做确定性准备，明确条件或必需条件错误时不调用识别模型；不明确请求继续受控模型识别。情绪旁路默认关闭。准备结果携带 specification，组装阶段复用，避免再解释用户条件。
- `EvidencePresentation` 由已校验归属的证据生成覆盖说明，视频范围、帧位置、采样限制和转写状态不会由回答模型覆盖；交付检查任务所需证据种类。该检查不宣称能自动证明自然语言结论的语义正确性。
- 视频 Prompt 区分系统时间标签与原始字幕，禁止没有明确画面证据的连续变化断言；缓存版本同步提升到v3。是否改善真实输出仍需候选版本同素材回归，不能以提示词更新宣称质量问题已验收。
- `BusinessEvidencePolicy` 依赖受限 `EvidenceContext`，不能直接调用 RunState 的终态方法。`LoopControl` 不再依赖 OTel 或 Harness；通过可选耗时回调观测，回调异常不改变执行结果。RunState 保留同步持久化和终态仲裁职责，不做全量纯领域对象迁移。
- `RunRepository` 不再继承报告和会话端口。业务身份适配器只读取 `ResourceScopeStore`。`MysqlConversationStore` 承接历史读取、记忆构建与缓存键/有效期逻辑，权限和活动任务检查仍委托原写入方；恢复、outbox、清理和终态事务继续保留在 MysqlRunRepository。没有新增事件总线或改变事务锁序。

针对性回归检查时间范围、工具上限、准备阶段跳过/回退、可信覆盖说明、观测异常、历史权限过滤和损坏数据。真实 MySQL/Redis 集成需要独立 `_it` 数据库；本机 Docker 引擎不可用时保持跳过，不使用业务数据库替代集成环境。

本轮验证：Agent `mvn verify` 运行248项测试，0失败、0错误，10项外部集成跳过；前端10项协议测试通过。打包服务的 HTTP/SSE 冒烟通过，覆盖认证、FAQ、指标、私有报告、唯一 DONE、Trace 关联及载荷脱敏；明确任务的识别调用数为0，跳过阶段有记录。迁出的4条会话 SQL 与迁移前语句逐一一致。本轮无真实模型收费调用、线上部署或数据库迁移。发布扫描仍有既有部署文件中的8项待审项，没有新增。

待验收：独立 MySQL/Redis 环境中的真实事务与恢复，以及候选版本对同一视频的真实语义回归。恢复、outbox 与清理仍在运行仓储中，后续只有在实际复杂度或故障证据支持时再拆分，不宣称整个运行状态已完全解耦。

## 验证边界

默认回归无需付费模型。OTLP 验证使用本机 HTTP Collector fixture，视频模型使用受控 fixture。外部 MySQL/Redis 集成未配置时仍按原开关跳过；报告存储拆分的真实事务、服务器 Collector、真实模型与负载容量需要在隔离验收环境继续验证。未运行服务升级、数据库迁移、线上部署或 Git 推送。


## A02 / H02 来源契约边界（2026-11-01）

准备层 AnalysisSourceSelection 解释明确来源，TaskMeaning 冻结 AnalysisContract 到 Specification；应用层 AnalysisExecutionPolicy 供 ToolDispatcher、DeliveryService 与 AgentRuntime 共用准入、覆盖和轮次规则。core 只承载不可变数据，不依赖查询、报告实现、运行状态或模型。工具不得自行重读原文决定必需来源，也不能在来源未选择时扩大查询。

反馈适配器负责选择实际端点：COMMENT-only 只读评论，DANMAKU-only 只读弹幕，二者同时选择才调用联合一致快照。AudienceReportData 的未选来源空结构仅供呈现归一化，不代表查询零结果；selectedSources 随证据、报告文档和缓存保存。交付校验覆盖所选来源；ReportArtifacts 仅在 ReportStore 真正保存后记录本轮回执，DeliveryService 校验回执及证据归属。视频报告复用同一私有产物边界。

会话焦点保存已确认任务，来源追问保留原对象/统计区间；不凭历史授予权限，业务身份适配器重新校验会话资源。旧 Specification.analysis、Focus.task 缺省可读，既有 SQL 迁移校验和保持不变。自然语言解析采用保守显式语法，模糊条件先澄清；确定性完成条件不等于自然语言结论质量证明。


## A01 报告进度边界（2026-11-01）

HostContext 的 reportClassification/saveReportClassification 委托给按任务绑定的 ReportProgressService。宿主保留“只有 create_danmaku_report 能写进度”的能力检查；服务独立检查证据归属、分类前缀、成员唯一性、每主题条数、完成标记和视频证据，再写入既有私有 ReportCheckpoint，成功后更新可丢弃的 ExecutionState 缓存。历史分页仍在宿主，留待下一批。

服务只依赖受限 EvidenceContext 和执行数据，不持有具体 RunState，不调用模型、Harness、工具实现或存储适配器。恢复优先选择本轮最高 offset/merged；最高进度损坏或同位置有不同草稿时明确拒绝，不任意选取或静默降低进度。合法缓存进度可跳过已完成批次，但同样需要通过状态准入；重复保存相同状态不新增检查点。旧 JSON、私有证据端口、查询权限与最终报告覆盖规则保持。

ReportDraftEditor 继续负责模型字段解析、批次和主题合并，ReportAnalysisCache 继续负责相同授权快照的分类缓存与租约，ReportArtifacts/DeliveryService 负责实际 HTML 与成功交付。报告串行更新约束和单写实例不变；本次不增加通用工作流框架或新的报告工具。


## A01 历史查询边界（2026-11-01）

HostContext.history 只检查运行状态并调用只读 HistoryQueryService；服务固定 session/owner/turn，负责参数约束、当前轮次上限、页内搜索、截断、游标和结果组装。ConversationStore 负责会话归属、授权范围过滤与有界升序数据；messages 的统一窗口为50条，before 为排他序号，数据已过权限隐藏才交给应用服务搜索。服务核对返回页的上限、顺序、唯一性和序号范围，异常页拒绝返回。

保留已有分页行为：若尚有未返回匹配，游标取本次最早返回项；否则取整个已检查窗口最早项。满50条或尚有匹配时 more_available=true；空匹配窗口也能继续前进，恰好50条的最后一页可能需要一次空读确认结束。服务每次只调用一次存储，不自动无界扫描。完整可见文本先搜索，再按原1600个 UTF-16 单位上限安全截断，文本长度不参与游标。

查询服务只接收不可变的会话/权限/轮次和 ConversationStore，不持有运行状态、执行状态、模型或工具实例；读取旧指令不能修改冻结任务、焦点或记忆。工具参数、响应字段和历史权限策略保持兼容，SQL 仅把既有50条常量提取到端口契约，不改变查询条件。实现范围和验收见根目录 ROADMAP A01 第二批。


## A04 原生工具历史配对（2026-11-01）

HarnessContextBuilder 消费 ExecutionState 已按执行顺序保存的 observations/exchanges，两者一一对应；相同结果不表示同一次调用，不能按结果内容反查第一条 exchange。构建临时视图前固定调用参数、原生 ID 和组；多个原生组保持独立，结果正文投影和历史整轮裁剪不改写该关联。

无 exchange 的旧构造方式继续生成宿主 ID；有 exchange 时必须完整、一致，缺 ID 只补唯一宿主标识而保留已知参数，真实 providerCallId 不被宿主编号覆盖。数量不符、空记录、重复 ID、组不连续或过大均在发出 HTTP 请求前失败。Context Hook 不能把原生执行账本单独删改或降级为旧格式；TOOL_RESULT 转换发生在入账前，完整账本可用于后续只读投影。P1 的新淘汰策略和 ContextPlan 留待下一批，不在此处增加新的摘要层。


## A04 报告上下文投影（2026-11-01）

ReportContextProjection 位于应用层，仅依赖 core 数据与 JSON，在 HarnessContextBuilder 已固定原生调用配对后接收结果副本。它不访问模型、工具、运行状态或存储；原始 execution 账本和证据不变。当前仅处理 create_danmaku_report 的已接受 topics_json，以及后续进度已完整覆盖的旧分类正文；保留最新累计主题和未读 groups，每项仅在实际序列化变小时采用。

确认资格来自宿主准入后的同证据分类进度，而非“模型已经读过”。TOOL_RESULT 转换不得删除或修改 classification；投影后的历史参数带 view-only 标记，不能作为重放调用。调用 ID、组和 tool 回复保留，反馈原文继续按私有证据 read_result 回查；完整原始参数留在执行账本，不通过 read_result 恢复。

普通评论、历史、Skill 和 read_result 不因已读而移出。未新增摘要事实、外部存储、SQL 迁移或模型调用；harness.system3.3.0 说明投影语义，已有缓存版本随 Prompt 内容更新。原始 Context Hook 和模型字节上限保持，超长执行账本保护及整请求预算仍是后续边界。回归范围见根目录 ROADMAP A04 第二批。


## A04 当前报告状态（2026-11-01）

ReportTaskStateView 通过 EvidenceContext、ExecutionState 和既有 ReportProgressService 读取已确认进度，不持有 RunState、不调用模型/工具或存储适配器。只选择当前运行及 owner 下、符合冻结查询和文本来源的完整反馈证据；checkpoint 恢复继续沿用原校验，损坏状态明确失败。reportStored 来自实际报告保存成功后的 reportReady 回执，不能从分类 offset 推断成功。

core.ReportTaskState 是一次性不可变视图，不是新的持久化状态或交付策略。Runtime 在 CONTEXT transform 前生成，TransformInvariants 禁止删改；模型适配器只负责把它编码到工具历史之后的 task_state 系统消息，不把反馈正文提升为宿主规则。旧 ModelContext 构造器缺省为空，非报告流程不被赋予虚构进度；原始账本和证据保持。harness.system3.4.0 说明组数、合并和报告存储的区别。

专项回归检查拒绝后进度不前进、移出后正常工具回查、多批报告落库及冻结任务不变；受控决策验证机制，不替代真实模型语义评价。验证日志与剩余预算边界见 ROADMAP A04 第三批。


## S01 报告能力说明与执行契约（2026-11-01）

System 保留来源、信任、覆盖和报告实际保存要求；Skill 承载具体报告分析方法；Tool 描述输入/结果、分类兜底和产物时点；现有 Java 策略继续执行准入、覆盖与保存。说明整理不得改变业务规则，也不新增一套可与 Java 冲突的执行状态机。

报告路径按实际证据区分：纯 VIDEO 请求才单独提交视频 evidence_id；query_danmaku 的完整弹幕分类使用 T1..T6；query_audience 的所选反馈使用 T1..T100，即使只读一种反馈。OTHER 独立保留；空成员主题忽略、重复归首次。遗漏成员复用当前批首个非空“其他讨论”主题并保留其键，不存在时才新建 OTHER；跨批次以返回主题键为准，模型仍须逐批理解并主动覆盖。无反馈不跳过所选视频，中间进度不是已保存报告。新增行为回归与版本见 ROADMAP S01 第一批；工具参数 Schema、生产 Java 和 SQL 保持。


S01 独立 review 后明确了非报告边界：reportRequired=false 的混合分析继续使用已确认任务对应的分析 Skill（comments.analysis 为 comment-analysis），不得因加载 video-content 切入报告流程。同名兜底的 T1/OTHER 行为不改 Java，使用41组两批的行为案例核对；补丁版本和验收见 ROADMAP S01 Review 修复。


## S02-A 字段说明与模型Schema（2026-11-01）

ToolCatalog 仍支持有限Schema，仅允许字段附带可选description并校验非空/长度≤512；原类型、必填、未知参数拒绝和有界对象数组规则保持。ToolArguments 不读取description，不把它当新参数或执行策略；说明不授予权限。ReadSkillTool 在原name字段副本更新枚举，保留说明和约束。

参数说明在声明工具资源中维护，既有TaskAssembler工具指纹覆盖其内容；不为说明引入第二套注册表。模型适配器通过原生tools.function.parameters传递完整Schema，包括数组内字段；说明占用也由既有整请求检查约束，超限不得静默删工具定义或扩大预算。当前39处说明不等于真实模型可用性收益证明；验收范围与日志见 ROADMAP S02-A。
