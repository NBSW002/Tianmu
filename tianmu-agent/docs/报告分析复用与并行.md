# 报告分析复用与并行

## 执行边界

Skill、Tool 入口、模型与生成提示词保持原有职责。确定性应用服务负责复用、租约、预算及并发；模型继续逐批阅读全部成员，汇总保持现有语义生成。报告仍默认展示五个主要话题，全部证据保留。

每次请求重新授权、导出当前范围快照并准备评论与弹幕。之后每个 CLASSIFY / MERGE 单元按实际输入指纹查找已通过成员与叙事校验的 Proposal。命中后重新绑定当前任务成员、校验全量覆盖、写入当前任务证据，再渲染当前报告模板；不复用旧任务证据 ID 或旧 HTML。原任务文件清理不影响独立保存的缓存内容。

指纹包含租户、用户、videoId、选择的数据源、规则版本、模型与提示词策略、全部分组原文/原始 ID/回复上下文/作者标记/播放时间、话题目录，以及实际使用的视频版本事实。MERGE 使用与模型相同的规范化材料，成员别名 C1… 在当前任务中重新绑定。查询终点随当前时间变化但实际成员未变时可复用；编辑、删除或新增成员改变输入后失效。新请求的统计与时间范围来自新快照。

`FEEDBACK_RESULT_REUSE_WINDOW` 默认 `10m`，这是结果 TTL。窗口内也必须匹配当前输入，窗口到期重新推理；目前没有“窗口内完全免读数据”或“到期后仍复用”的快速路径。`FEEDBACK_RESULT_REUSE_ENABLED=false` 或窗口 `0s` 可关闭。最大缓存条数 `FEEDBACK_RESULT_REUSE_MAX_ENTRIES` 默认 1024，每条 JSON 不超过 128 KiB。V13 在 MySQL 保存缓存、自有内容和短租约，生产重启后可恢复；demo 无数据库时使用内存。

明确的“重新分析 / 重做分析 / 绕过分析缓存 / 强制刷新分析”在任务准备时冻结 forceReanalysis，跳过后台分析复用；仍允许复用未变化的视频事实和向量。全量成员和证据校验不跳过。失败或被租约拒绝的单元不发布缓存。已验证单元可以复用，即使其原任务后续其他步骤失败，最终报告仍需当前任务完整收敛。

## 同时请求与权限

相同 key 的未命中请求选举一个短租约持有者，模型调用与 Token 归其任务；等待者不重复调用模型，独立检查取消和截止时间。SQL 事务只覆盖选举与发布，不跨模型调用；发布检查租约 token，过期持有者不能覆盖新结果。持有者失败后释放租约，其他任务可重新选举。等待使用现有有界后台工作池，每 100ms 检查，依然占用一个工作线程。

每个任务在开始、接受单元、读取资产和报告交付路径继续独立授权，缓存按租户和用户隔离。缓存不可用时按既有持久化错误重试，避免绕过账本直接扩大模型调用；缓存发布失败不丢弃已接受的当前结果。

## 读取并行

`FEEDBACK_READ_PARALLELISM` 范围 1–4，默认 1。新链路先完成第一批作为不可变种子目录，随后最多 N 批 CLASSIFY 并行。所有并行批次看到相同种子目录；新话题 ID 仍属于各自工作单元，最终语义汇总合并相似主题。只有该层所有单元完成才进入 MERGE，MERGE 保持串行。旧链路保持串行。

工作领取在父任务锁下检查并行数、租约、预算与 fence；任务取消通知所有在途单元。工作池和队列有界，不为每批创建无限线程。首批、汇总及前台主循环耗时仍存在，并行不能按调用时长简单相减。上线先保持 1，须对同源强制重跑进行质量和耗时对照后再调大。

## Trace 与验证

命中记录 `analysis.cache_hit`、`analysis.cache_age_ms`、`analysis.cache_source_job`、`analysis.cache_wait_ms` 和 `analysis.force_reanalysis`；命中不伪造 model.request 或模型用量。等待时间、排队、模型耗时与数据库/对象 IO 分开查看。

本地测试覆盖新任务证据重绑定、原任务文件删除、窗口到期/禁用、强制重跑、模型/用户/原文变化、共享等待取消与失败重选、首批屏障、并行重叠、完整覆盖及准确预算；视频测试覆盖持久保留、有限保留期、容量与来源匹配。真实供应商耗时与线上 MySQL 行为应单独记录，不能用 mock 的 0 调用测试推算线上总耗时。

## 2026-11-07：Agent 通用工具并行调研补充（待实施）

本节是研究结论和拟议实现，不表示已经部署。已有反馈分析 worker 的并发与主 Loop 的工具并发分别验收。

当前 `AgentRuntime.iteration` 支持单次模型决策包含多个调用，但执行仍为串行循环；`ToolDispatcher.checkBatch` 限制 2–4 个调用。当前显式开放 batchable 的处理器只有视频内容分析、弹幕分析、评论分析，且弹幕/评论来源准备批次不能混入其他工具。因此不能声称目前任意读取工具都可以批量或并行执行。

Anthropic 的[并行工具协议](https://platform.claude.com/docs/en/agents-and-tools/tool-use/parallel-tool-use)区分模型一次输出多个调用和宿主如何执行这些调用；执行顺序由宿主决定，结果必须保持调用 ID 配对。[LangGraph ToolNode 源码](https://github.com/langchain-ai/langgraph/blob/main/libs/prebuilt/langgraph/prebuilt/tool_node.py)可参考其独立调用、错误处理和结果汇合方式，不直接引入 Python 框架。[JDK 17 CompletableFuture](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/CompletableFuture.html)的取消不等于底层计算停止，因此超时和取消必须继续传递到底层 IO。

拟议流程：模型输出批次 → 全批准入检查 → 固定工具可见性与上下文快照 → 有限并发执行 → 主协调器按调用顺序提交结果 → 一起装入下一轮上下文。

- 保留现有 2–4 个批次上限，初期单 run 实际并发建议为 2，并设置全局并发、队列和资源隔离，参数须经实测确定。使用现有 Spring 执行器/预算/取消/Trace 机制，不能使用无上限公共线程池。
- 将 batchable 与 parallelSafe 分开：前者仅允许同轮表达，后者还需确认无依赖、状态隔离及副作用边界。初期只开放已审查的独立读取；激活 Skill、修改记忆、发布及资源创建保留串行。
- `ExecutionState` 存在同步方法不代表复合调用天然安全。分支只能读取固定快照，返回结果、证据和依赖的增量；协调器统一提交 exchanges、记忆依赖、进度与交付状态。尚不能输出增量的处理器不进入并行白名单。
- 每个调用保留原始 tool_call_id，成功、失败、超时各生成一个配对结果；完成先后不能改变消息配对。可恢复的读取失败允许与成功结果一起回传，权限撤销或请求取消终止整个批次，禁止把错误当作空数据。
- 批次共用 run 截止时间和预算，各分支有自己的调用控制；不能因超时而释放名额却让底层 IO 无限运行。失败重试只针对允许重试的分支，避免重放已成功的副作用。
- 弹幕/评论等持久任务继续复用现有 operation group、outbox、租约和幂等机制；仅提交顺序变化不等于后台工作已经并行。进程重启恢复不得重复创建任务。
- Trace 用真实 batch 父节点承接多个 tool 子节点，记录批次序号、调用索引、执行模式、排队/执行时间与结果。只有实际重叠的执行可画成并行；provider 子 span 保留在各自工具详情。

验收：用屏障证明独立工具真实重叠；反向完成仍保持 ID 与结果配对；混合成功/失败、取消、队列满和撤权均可收敛；状态只由协调器提交；来源任务重启不重复；Trace 父子关系、用量与实际执行一致。速度收益以服务器受控场景测量，不预设所有任务都能按工具数等比加速。
