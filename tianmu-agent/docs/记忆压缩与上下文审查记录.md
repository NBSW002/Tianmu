# 记忆、压缩与结构化上下文审查记录

日期：2026-11-07。范围：本批 Agent 后端、相关前端、V17–V22 迁移与配套架构文档。审查不包含独立进行的视频上传重构。

## 独立审查结论

本批由独立 reviewer 进行只读代码审查，另由实施者执行回归与真实模型验证。最终复核确认，下列 1 项 P1 与 3 项 P2 均已闭合，未发现新的阻塞问题。该结论不表示已经完成未改动业务系统的全面安全审计，也不替代大规模记忆质量评测。

| 等级 | 问题 | 修复与回归 |
| --- | --- | --- |
| P1 | 自动提取读取来源后、实际发送前若发生暂停、清空或删会话，旧原话仍可能发送 | extractionBarrier 在真实 dispatch 重验账户模式、自动提取授权、epochs、会话/run 存活及 job lease；结果后和发布事务继续检查。新增阻塞发送期间 reset/pause/delete 竞态及实际 HTTP 两路径零请求测试 |
| P2 | 压缩旧 worker 租约失效后仍可能发送并重复消耗模型 | compaction dispatch 增加 lease authority 检查；新增丢失租约后零 provider 调用测试 |
| P2 | 手工 SESSION 记忆没有完整会话来源生命周期 | 本批公开 API 与手工存储均拒绝 SESSION；会话摘要使用独立 projection/member，不假装手工 SESSION 已支持。新增 HTTP 拒绝测试 |
| P2 | 记忆遗忘后，浏览器已展开正文仍留在缓存 | 成功管理变更和记忆工具完成发出无正文失效通知；Usage abort/清空/重取，Manager 处理其他标签页与同 tab Agent 操作；区分自身写入避免中断。使用 BroadcastChannel 与 storage 兜底，新增来源区分及跨 tab 测试 |

## 前序复核与额外加固

前序审查发现的压缩单独启用时跨轮依赖丢失、固定摘要从最新窗口恢复导致误失效，已分别由共享 MemoryLedger 继承和按固定 ID 恢复修正。摘要成功与后续整理检查通过同事务 outbox 落盘，避免重启漏整理；SQL 故障注入验证事务回滚后可幂等重试。

Trace 在启用记忆或压缩时从绑定开始保护原文，避免根 span 提前留下未追踪副本。model.dispatched 只在强校验通过、准备调用 sendAsync 后标记；被来源屏障拒绝的调用不能显示为已发送。Trace 保留实际模块、引用、字节、状态及模型用量，正文按当前权限回源。

## 验证边界

验证包含真实隔离 MySQL、来源删除与账号隔离、24 轮后台追赶、固定上下文槽位、原生工具配对及读回、前端通知与构建。两组真实模型样例通过正常 DeepSeekMemoryModel、上下文协议和预算链路，分别验证否决方案保留、草稿状态及未获发布授权；保存了真实请求子 span、用量和压缩字节。

真实模型样例使用虚构会话，不向业务视频发布内容，不代表已经达到方案中的 95% 质量目标。服务器发布须另行核对所部署 revision、数据库迁移、账号授权、真实模型和 Trace；本文件不预先宣称服务器验收通过。
