# Agent 分析与报告接口契约

反馈分析统一为 `analyze_feedback → read_result / create_feedback_report`。不再提供原文分页分类工具或迁移开关。

来源、视频、反馈时间和视频播放区间由 confirmed_conditions 冻结。COMMENT/DANMAKU 的后台流式快照、批次语义分类、层级归纳和覆盖检查由 FeedbackAnalysisService 完成。选择 VIDEO 时先调用 analyze_video_content，并把本轮同一视频的 video_evidence_id 传入 analyze_feedback；没有选择 VIDEO 时不读取画面。

analyze_feedback 返回持久作业等待状态；宿主挂起主 Agent，后台执行。等待期间不轮询主模型。READY 返回本轮私有 evidence_id 和准确 counts。失败、超量、授权过期和取消不能当作完成，不回退抽样路径。

reportRequired=true 时，READY 后仍须 create_feedback_report 保存私有 HTML 并交付。空数据也保存空报告。reportRequired=false 时，read_result 顺序读取全部上层 topics 后回答，按需通过 children、originals、original_text 下钻。原文分页按 Unicode 字符，topic_id/original_id 必须属于同一证据。

纯 VIDEO 报告单独使用 create_video_report(evidence_id)，只允许来源恰为 VIDEO 且确实要求报告的任务。视频报告不能替代反馈报告。danmaku.overview 数量与时间范围查询保留 query_danmaku；它不提供分类进度。

智能评论与智能弹幕共用后台分析证据、原文与主题读取能力，分别通过 prepare_comment_draft / prepare_danmaku_draft 生成草稿。发布仍需页面确认接口。

旧报告 HTML 和历史证据保持可读。ReportCheckpoint/DanmakuClassification 仅保留历史反序列化数据格式，不再存在写入、恢复执行或缓存续跑入口。持久化数据库历史迁移不回删。

后台模型输出采用 `topics + assignments`：每个输入 ID 只对应一个主题键，代码生成主题成员与次数，仍严格核对完整覆盖。缺失或无效引用会被拒绝；纠错资料与当前批次一同保存到私有对象中，并由原有租约版本控制更新。下一次重试获得明确的缺失、重复、未知 ID 和上一份分类参考，不把不完整结果当作已接受进度。重试上限、预算、取消和授权检查不变。
