# 反馈报告粗排与精排技术方案

更新于 2026-11-10。新版 `feedback-five-rerank-v1` 已在站点 Agent 发布，发布镜像为 `tianmu-agent:20261110-rerank055`，有效阈值为 0.55，精排模型为 `qwen3.7-text-rerank`。本地默认关闭。旧协议的工具及交付边界见[代表材料三工具实施与验收](代表材料三工具实施与验收.md)。

## 1. 基线和目标

当前五桶协议在授权快照内清洗、去重、复用向量并补缺，再以球面 K-means 形成最多五桶。规则每桶挑最多八条，分析模型按实际任务分批分析，配置开启时再全局复核。候选桶数与最终主题数耦合，候选边界和代表材料的质量决定模型还能看到哪些观点。

| 线上回放入口 | 观察 |
| --- | --- |
| heller菌 `9cc8638e8cd9486ac0c0461dac528906` | 300 条原始反馈，278 条通过预处理，185 条未归类。最大桶 57 条，分析候选 8 条。相近的游戏名改词分散在多个桶，未归类示例有广告。267 个表达在报告时计算向量，缓存命中为零。 |
| 鸭子视频 `ad827dfb80058761577c7c00dbd6442b` | 240 条通过预处理，145 条未归类。同视频重复 Trace 合并为一个评测样本。 |

首版同时验证两个目标。质量上保住重要主题和少数观点，减少混桶、重复主题和不相干的原话。成本上把全局生成放到证据筛选之后，反馈分析模块每份新报告最多派发一次生成请求。外层 Agent 调用、向量补算和预热开销分别计账。线上预热零命中原因待查，和分桶质量分开定位。

## 2. 默认流程和模型

```text
评论 / 弹幕落库 → Canal → 按视频合并的持久工作队列
  → qwen3.7-text-embedding 批量生成缺失向量 → Milvus

请求报告 → 实时授权 → 固定快照 → 清洗和去重
  → 读同版本向量，缺失项按预算补算
  → 向量粗排，输出无主题名的候选桶和未分配表达
  → 本地筛选候选，用代表原话作锚点
  → 最多五个桶分别调用 qwen3-rerank，桶内独立排序
  → 合并排序与多样性配额，压缩全局证据包
  → deepseek-flash 一次确认主题、合并或拆分并生成报告
  → 程序校验引用、重算证据统计、授权交付
```

| 模型 | 首版在线次数 | 职责 |
| --- | --- | --- |
| `qwen3.7-text-embedding` | 预热按缺失项批处理。报告全命中时 0 次，有缺失时按批次及预算补算 | 提供表达向量，预热和报告补算共用版本与缓存键规则。 |
| `deepseek-flash`，现有 `ANALYSIS_MODEL` | 新报告有可用证据时最多 1 次。有效语义缓存命中、无可用证据或报告预算不够时 0 次 | 在同一响应里确认主题、选原话 ID、写观察与建议。 |
| 阿里云百炼 `qwen3-rerank` | 每个可排序的桶 1 次，每份报告最多 5 次。先回放并按验收门槛启用 | 对同一桶的锚点与候选反馈打相关分。授权、预算或可用性不足时走本地排序。 |

正式主题在最后一次生成时出现。粗排沿用最多五桶，每个有效桶取最接近自身中心且可独立理解的一条原话作为锚点。各桶先用已有向量筛候选，再独立重排。锚点与正式主题有表达差异，回放同时检查相关率、重要观点覆盖和口语梗的召回。

## 3. 粗排与本地精排

1. **准备。** 保留原始记录 ID、表达 ID、来源、作者角色和上下文映射。精确归并需区分会改变语义的父评论和时间语境。明显广告需满足多信号规则，单独出现链接仍可进入后续筛选。父评论、视频事实只作为语境。原站点赞带来源与采集时间，本站点赞独立，未知值保留为空。首版只消费已可靠保存的信号。
2. **粗排负责分组。** 复用最多五桶的球面 K-means 及单一主归属。每桶按中心相似度取最多 20 条送评表达。未分桶或超出候选上限的表达分别记录原因。
3. **选锚点。** 每桶取最接近中心且能独立理解的一条原话作 Qwen 查询。锚点从主成员中选，单独传入，不占该桶 20 个送评名额。
4. **确认材料。** 每桶只保留精排 Top 3，五桶合计最多 15 条。未分桶反馈继续参与覆盖对账，并作为候选召回的诊断样本。

### 3.1 数据契约与确定性选材

以下是首轮回放可直接实现的规则。阈值用调参集调整后冻结，留出集只验证。

| 阶段产物 | 最小字段 |
| --- | --- |
| `Expression` | 表达 ID、来源、快照原始成员 ID、上下文签名、向量引用、原话及可选语境的摘录位置。 |
| `Bucket` | 稳定桶 ID、最终中心、成员表达 ID、可选主锚点。 |
| `CandidateEdge` | 桶 ID、表达 ID、中心相似度、粗排名次、可选精排名次及截断原因。 |
| `RerankBatch` | 冻结桶 ID、锚点和摘录摘要、按发送顺序排列的表达 ID、请求摘要、模型/指令版本、发送意图及回执状态。 |
| `EvidencePack` | 唯一表达列表、允许引用的候选边、全局材料预算及实际字节/估算 token、证据包哈希。 |

1. **确定表达与中心。** 表达归并键包含来源、按现有规则规范化的正文和语境签名。评论回复以父评论 ID 区分语境，弹幕沿用现有时间分段，有片段摘要时追加摘要标识。向量缓存仍按现有正文与模型版本读取。沿用当前向量变换及对应的粗排阈值 `t`（当前配置类默认原始余弦 0.65，启用中心化时该模式默认 0.30）。复用球面 K-means 的初始化和迭代，最多 5 桶，最小桶 2 个表达，最多 50 轮和 64 个初始化采样点。按最终留下的主成员重算归一化中心。桶 ID 从排序后的主成员表达 ID 生成。
2. **确定候选。** 沿用现有聚类的单一主归属。每桶候选与桶中心的相似度须达到阈值 `t`，按相似度降序、稳定表达 ID 升序取最多 20 条，不足就用实际数量。先确定锚点，再从候选中排除锚点自身。已分桶但未进入这 20 条的表达仍保留在桶成员和覆盖对账中。
3. **选锚点和本地回退顺序。** 在主成员里按中心相似度从高到低选第一条通过现有 `contextDependent` 检查、能独立理解的原话，作为主锚点。没有合格锚点时保留桶及原始成员，用中心相似度的本地顺序取证。「确实」「这个不错」一类依赖语境的候选须带有效父评论或片段摘录才可送评。保留能独立指代内容的短词和梗。
4. **装包。** 每桶将 Top 3 表达及其桶 ID 放入冻结证据包。最多 15 条。总 token 超限时先裁可选语境，再按第 3、第 2、第 1 名的顺序裁证据，同名次按稳定桶 ID 的逆序裁剪。必需语境无法保留时同时移除该条正文及证据边。

合法证据边键为 `(groupId, expressionId)`，其中 `groupId` 是粗排桶 ID。

### 3.2 Qwen 精排的请求和合并

1. **逐桶执行。** 按稳定桶 ID 调度。存在主锚点且至少有 2 条候选时，每桶发一次 Qwen；只有一条候选时直接保留。
2. **冻结输入。** 每桶按第 3.1 节固定的粗排顺序送最多 20 条，保存文档索引到表达 ID 的映射。
3. **请求。** 一个桶一个 `query`，只用主锚点原话及必要语境。`documents` 使用候选原话和可授权外发的必要语境。使用百炼 `POST /compatible-api/v1/reranks`，按配置的区域和工作空间寻址。省略 `top_n`，收到完整分数后由宿主截取 Top 3。接口字段见[百炼文本重排 API](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/text-rerank-api)。

```json
{
  "model": "qwen3-rerank",
  "instruct": "按候选反馈与参考原话讨论同一具体问题的程度排序，允许相反观点，区分仅共享关键词的反馈。",
  "query": "参考原话：打到第二关画面一直掉帧",
  "documents": [
    "原话：第二关开特效就卡死",
    "原话：第二关我满帧，第一关才卡",
    "原话：第二关的背景音乐叫什么"
  ],
  "return_documents": false
}
```

4. **取 Top 3。** 校验所有 `results.index` 唯一、在范围内、结果完整，且分数有限。按 Qwen 相关分降序、原粗排名次升序排序，取最多 3 条。Qwen 成功时直接使用该顺序；超时、无锚点、无外发授权或回执校验失败时，从该桶原先冻结的候选按本地顺序取最多 3 条。各桶分数不跨桶比较。
5. **实现位置。** 在 `feedback` 模块的候选装包和报告生成之间加入精排工作，持久化冻结的查询、候选 ID 顺序、预算及结果引用。供应商 HTTP 适配器处理请求、回执和取消。通过租约栅栏接收结果。重启只复用同版本且已提交的桶结果，状态未知的尝试计入预算并走本地排序。按既有授权和数据外发策略检查候选，仅送必要摘录，不发送用户 ID、点赞或其他个人资料。模型、指令、候选上限和 Top 3 规则进入协议指纹。

例如某桶送评 20 条，粗排第 8、3、11 名分别获得最高的三个 Qwen 分数，则该桶按 8、3、11 的顺序向报告提供证据。主锚点只用作查询，不额外补入报告。

## 4. 全局确认、证据和交付

模型收到已冻结的证据包。每条包含表达 ID、可引用的组 ID 列表、来源、原话摘录及必要上下文。输出严格 JSON，最多五个主题。每主题至少两个不同的表达 ID 作为证据，并选择其中一至三条展示。一个表达即使有多条候选边或多个等价原始成员也只算一个。输出预算不足时先缩短字段或减少主题数量，保留完整 JSON。主题 ID 由宿主根据有效证据边生成。最小回执示例如下。

```json
{
  "topics": [
    {
      "title": "第二关开启特效时的帧率",
      "observation": "有观众遇到卡顿，也有人反馈同一关卡运行流畅。",
      "recommendation": "优先复现特效开启后的帧率变化，并补充设备信息。",
      "evidence": [
        {"groupId": "b1", "expressionId": "e01"},
        {"groupId": "b3", "expressionId": "e12"}
      ],
      "quotes": ["e01", "e12"]
    }
  ]
}
```

模型可以像示例一样用多个桶的表达确认同一主题。拆桶时分别输出主题与证据边，每个拆分后的主题都须有两个不同的表达 ID，不能继承整个桶。允许同一表达支持两个主题，但重叠的两个证据集合必须各自至少有一个对方没有的表达。遇到集合相同或包含关系时，按响应顺序保留首个通过验证的主题并记重复原因。报告总览由宿主按有效主题组装，避免丢弃非法主题后正文仍提到该主题。

宿主校验主题、字数和条数约束，每条证据边必须存在于冻结包，展示 ID 必须属于该主题通过校验的证据。标题、观察、建议分别最多 24、120、80 个 Unicode 码点。回执未满足主题约束时整项丢弃；非法 JSON 或所有主题丢弃时，交付明确标记的覆盖说明，不调用模型修复。原话从对应快照摘录位置读取，并附来源和定位。模型指令要求观察中的主张与证据一致，建议写成待验证行动。程序只验证引用与形状，语义支撑仍靠回放人工抽检。

统计分别保存快照对账和报告证据覆盖。用原始记录 ID 去重，逐项核对 `原始 = 排除 + 可分析`、`可分析 = 已确认主题证据成员并集 + 未确认`。同表达的重复成员只有正文和实际评分语境等价时才计入。主题间可重叠，全局并集只计一次。页面标明「支持该主题的已确认反馈」，候选桶大小只用于诊断。未确认按缺向量、低置信、预算截断、未被主题采用等互斥计数，样例先过噪声规则。作者发言和父评论语境按原记录角色独立对账，只有其本身是合格观众反馈并获确认时才进入主题统计。

未确认原因按表达走过的最远阶段确定。已装包但未获有效主题引用记 `NOT_CONFIRMED`。进入精排但没进 Top 3 记 `RERANK_OUT`。因 Top 20 或请求 token 上限未送评、或入选后因报告 token 上限未装包记 `BUDGET_CUT`，另记具体阶段。锚点本身记 `ANCHOR_ONLY`。有向量却未通过语境或粗排候选规则记 `NO_RELIABLE_CANDIDATE`。无可用向量记 `VECTOR_MISSING`。

例如两个桶分别含 20 条和 9 条主归属反馈，最终合并时只确认 `e01` 和 `e12`，两者各对应 3 条和 1 条等价原始记录，则主题显示「4 条已确认反馈」。两桶的其他记录不会自动转成主题成员。首版用这 4 条说明证据覆盖，不据此推断该意见在 29 条反馈中的占比。若业务要全量主题分布，需要单独评估确认后全量归类及误差。

## 5. 预算、降级和恢复

以下为回放的起始参数，按留出集验收前冻结，配置生效时同时受现有执行策略更严格的上限约束。

| 项目 | 实验预算和截断方式 |
| --- | --- |
| 粗排候选 | 最多 5 桶，每桶最多 20 条，合计最多 100 条，锚点单独作为查询。 |
| 全局证据包 | 最多 15 条不同表达，每桶最多 3 条。每条原话摘录最多 256 个 Unicode 码点，上下文最多 256 个。按第 3.1 节裁剪后，全包至少有两条独立表达才派发 DeepSeek，否则直接交付覆盖说明。 |
| 生成模型 | 1 次请求，输入目标上限 4096 token，输出请求上限 1024 token，计入系统指令、结构约束和元数据。派发前用经验证的模型计数或保守上界做预估。计数上界未经验证时只允许离线测量。 |
| 向量补算 | 沿用现有独立批次、截止时间和预算，超限时带缺口说明。预热费用以批次单独计入端到端对照。 |
| Qwen rerank | 最多 5 请求、每请求 20 对、总计 100 对。单请求最多预留 2048 输入 token，整份报告最多预留 10240。按查询在候选中重复计入预估用量，并为指令和协议开销留余量。生产准入前验证保守估算，按供应商 `usage.total_tokens` 对账，超预留按实记账并停止派发剩余桶。单请求 1.5 秒，阶段总截止 5 秒，最多 2 个并发且不重试。 |

Rerank 派发前在同一事务按「任务 ID + 冻结桶 ID」写入唯一发送意图，并预留整个任务的请求次数、文本对数和 token。超额先减候选，少于 2 条则跳过。发送意图跨租约生效，状态未知也不补发，HTTP 和代理禁止重放。精排阶段绝对截止时间持久化，重新领取时沿用。预算耗尽、429、超时、字段错误或无外发授权时，对应桶回退本地排序，其余桶继续。降级报告标明回退原因，排除在正常 Qwen 报告缓存之外。同范围的材料结果缓存命中时跳过 Qwen，确认结果缓存命中时跳过 DeepSeek。只有两层都命中时两种模型均为零调用。可用证据包构建完成后仍只允许一次 DeepSeek 请求。预算参数、模块开关和并发上限随任务冻结。

生成子预算复用 `FeedbackBudget` 的请求前预留、供应商回执对账和未知用量保守计费。发送前在当前租约下以原子操作预留额度并写入该任务唯一的发送意图，只有写入成功且通过派发屏障的工作者可发送。首版关闭模型修复，禁止工作层、模型客户端、HTTP 传输及可控代理自动重放该 POST。新工作者遇到发送意图，只能复用已提交结果，或在当前租约失效后以有标记的覆盖说明收尾。即使崩溃发生在写入意图之后、实际发送之前，也按未知状态保留原预留。成功、超时、解析失败或响应丢失均消费已使用的额度。调用前和交付前均重新核验实时权限。授权撤销、取消或任务截止后阻止交付。

缓存复用绑定授权范围、快照哈希、规则版本、提示词、模型、选材参数和呈现协议。只缓存校验通过的正常报告。证据包、阶段记录和回执使用既有私有对象存储与持久任务，按租约栅栏提交。Trace 写阶段计数、决策原因、耗时、派发次数、预留与回执用量，原话正文从授权产物读取。报告页面区分正常报告、证据有限和生成失败。

## 6. 复用式改造与上线顺序

新协议暂名 `feedback-five-rerank-v1`。报告仍走现有工具、准备任务、分析任务和报告交付。改动集中在 `MATERIALS` 的选材尾段，以及报告分析的语义处理分支。

当前 `FeedbackTaskPolicy.compressedRequest` 固定写入旧协议。新版准入只在首次准备来源前读取开关，将选定协议写入 job。三工具、`FeedbackPreparationCoordinator`、`FeedbackOperationCoordinator` 以及 Delivery 恢复时，使用持久化 job 的 `request.rulesVersion` 重建期望请求并照常校验其他任务约束。把新版显式纳入 `representativeVersion`、原文读取屏障、材料指纹和报告解码路由，检查 `FeedbackMaterialEvidence` 的公共摘要和 `HistoricalReportReader` 的旧版统计分支。工具名和调用参数继续沿用。回归测试覆盖开启和关闭开关时旧、新在途任务仍能继续。

### 6.1 复用范围和接入点

### 6.2 两个持久化边界

1. **材料结果。** 现有 `Material` 继续提供工具消费的公共摘要和五桶成员视图。新协议增加可选的版本化证据包引用，旧记录缺字段仍可读。首个 Qwen 请求前以准备工作租约冻结整个计划，保存所有桶 ID、锚点、候选顺序、用于回退的本地分数、向量可用性指纹和绝对截止。之后重领只读这份计划，后来补齐的向量不得改变本任务的桶 ID 或生成新发送槽。使用同一共享来源快照分别校验可分析、已分桶和未分桶 ID。现有 `startCompressedReport` 的 assigned-only chunks 可继续用于旧协议；新版确认从冻结证据包及共享快照读取证据和定位，按桶内 Top 3 作为证据。新版分母来自共享快照对账后的全部可分析反馈，不能用旧版 assigned-only 计数代替。保存快照 ID 与材料哈希，重启不能重抓来源。
2. **付费请求和确认结果。** 现有 `reserveEmbedding` 与按 `(workId, fence)` 计的生成预留无法实现跨租约的一次派发。新增一个反馈模块的发送意图账本，唯一键为任务、阶段和稳定槽位（Qwen 使用桶 ID，DeepSeek 使用固定确认槽）。复用现有 SQL 事务与租约检查，原子写意图和预留，已完成桶保存结果引用。重新领取时只复用已提交结果，未知状态走本地回退或覆盖说明。确认结果单独持久化版本化主题和证据边，Asset 仍走已有完成流程。保留旧解码器，避免把旧报告迁成新统计口径。

启动配置为 `FEEDBACK_RERANK_ENABLED`、`FEEDBACK_RERANK_ENDPOINT` 和 `FEEDBACK_RERANK_API_KEY`，并复用现有压缩链路的启用条件。候选和证据上限、预算、超时和并发为本协议常量。跨任务 Qwen 缓存仅在同进程复用已成功的桶分数，绑定授权范围、查询区间、冻结策略和实际请求文本，不复用旧任务的原话对象。确认复用现有结果缓存，按同授权范围、请求区间、确认证据和视频语境隔离；回退结果不入正常确认缓存。任务内冻结计划和已发送槽位在 MySQL 中持久化。新版兼容读取和 V28 迁移先部署，再启用准入。关闭新版准入时保留读兼容版本及 Qwen 配置，在途任务沿用已冻结协议。运行资源无法共存时先排空受影响的旧任务。

### 6.3 最小实施顺序

1. **固定旧基线。** 用两条现有 Trace 和留出集保存五桶成员、原代表材料、最终报告和成本。验证评论与弹幕入队、预热、缓存读取；冷暖分别测量。
2. **先隔离验证精排。** 让旧五桶与新确认共用冻结候选，在相同证据预算下回放「纯本地」「五桶 Qwen」「只排三个混杂桶」三组。三桶模式用于成本对照。记录有价值的反馈是没有进桶、未进 Top 20，还是没进 Top 3。
3. **接入新确认和交付。** 添加输入、结果、预算账本与兼容读取，先跑快照、候选、模型适配器、故障及旧报告兼容测试。对同一输入断言最多一个确认工作、最多一个生成 POST、没有旧复核工作。覆盖五桶全精排、小桶跳过、一个桶回退而其他桶成功以及全回退。
4. **受控启用。** 新协议默认关闭，先回放和隔离影子，再少量准入。旧链路与新版按任务版本路由，记录每次结果的实际模式。质量和总费用过第 7 节门槛后才切默认。

## 7. 验收与决策

用上述两个 Trace 定位问题，另从已授权的视频里选不同题材、长短文本比例和噪声比例的样本。按视频分隔调参集和留出集。先标重要主题、少数观点、可引用原话及广告样例，再冻结样本和阈值。线上旧报告用于复盘，定量对照以同一快照、同一向量及固定模型重跑。

将每个标注主题按「快照中存在 → 进入粗排候选 → 进入证据包 → 成为正式主题」逐级对账。候选阶段命中以至少一条人工标注的相关表达进入为准，正式主题命中还要求主题边界正确且展示证据确实支持。区分单条孤立反馈、低频但有多条证据的观点、以及同主题的相反意见。分别记录遗漏的原因，避免只看整体相关率而把召回损失藏起来。

| 对照 | 读数与准入 |
| --- | --- |
| 现行五桶与新全链路 | 标注主题召回和证据相关率均不得下降，重要主题召回或证据相关率至少一项改善。少数观点覆盖和广告误入不得变差。原话、快照和权限对账通过率 100%。 |
| 新链路成本 | 新报告生成派发数最多 1。在双方均成功生成正常报告的配对样本上，报告模块平均生成输入加输出 token 比基线至少下降 20%，作为首轮实验门槛。全留出集正常交付率不得下降，以每个请求为分母计算的平均生成费用不得上升。两条路径用同一价格表分别核算输入与输出，计入失败和降级尝试，未知用量按预留额度和较高费率估算。另报 P50/P95 总耗时、外层 Agent 用量、冷暖向量耗时及向量费用，预热按批次和报告复用量单列。 |
| 粗排、精排与全局装包消融 | 比较候选主题召回、最终证据覆盖，以及关键反馈在哪阶段被截断。逐阶段记录五桶、Top 20、Top 3 和最终主题的覆盖。 |
| Qwen rerank 准入 | 用同一批桶、锚点、候选和报告生成预算，对比本地排序与 Qwen 排序。证据相关率或关键观点覆盖至少一项改善，另一项及少数观点覆盖不退化。相对旧链路，全样本每请求平均模型费用含生成、rerank 及补算不得上升。另报相对本地精排的边际费用与阶段 P95，阶段 P95 不超过 5 秒。以返回顺序打乱、索引越界、缺项、429、超时和重复领取测试回退。 |

本地测试已覆盖模拟供应商端到端、五桶调用与单桶限流、缓存全命中和部分命中、旧报告 HTTP 回归、预算预留前后重领、回执乱序及传输层禁重发。V28 已在独立 MySQL 库验证迁移和租约接管，生产迁移及 Agent 就绪已确认。

线上同范围样本比较了 0.60、0.55 和 0.50。三个原始回执都提议了主题，但误把引文正文放入引用 ID 字段。修订为短证据别名，引用字段失配时只从该主题已经校验过的证据选取展示原话。0.55 在该样本减少了重复短梗主题，并保留有上下文的评论。生产 Trace `b0a0c24fbcf6d11063ea59d6898627f0` 对 300 条反馈生成 4 个主题，确认 13 条反馈，核对 11 条展示原话。该样本的验收结果尚不能外推到所有视频。跨题材留出集及生产故障注入待继续验证。

## 用户报告展示调整（2026-11-11，本地）

HTML 按观察、代表原话、补充原话、建议的顺序展示，首条引文默认可见，建议只展示一次。弹幕位置图提前，按实际分段宽度绘制柱形，保留分段计数。统一小圆角及直边引用，减少嵌套卡片。

内部视频 ID 只用于链接目标，不作为可见标题或浏览器标题。已有视频标题时展示标题，缺失时使用“这条视频，观众怎么说”，不能用编号代替。当前报告生成资产尚未接入正式视频标题和封面，不能将该降级标题描述为已完成视频身份展示。回复上文解析为自然语言；异常时仅提示暂时无法展示。内部覆盖枚举、JSON、证据成员、分桶等实现词不直接输出到用户报告；统计限制改为普通读者能理解的说明。旧报告原有主题和建议不会因重新排版被修正，需要另行重新分析验证。

验证包括模拟端到端引用、展示顺序、建议不重复、标题转义及缺失标题、机器时间和内部字段不外露，以及本地浏览器截图。尚未部署，不代表真实模型主题质量已通过验收。

同日本地展示修订：删除独立阅读说明卡片与按发送日期入口，仅保留一行来源说明；图表的缺失记录和计数表收进详细数据。正文、标题和坐标统一无衬线字体，桌面 1280px 与手机 390px 截图验证，检查实际字体及页面横向溢出。话题只显示非零引用来源，建议标签改为“创作建议”。确认模型提示要求给出有原话依据的具体创作决策，没有行动依据时留空，不把外貌调侃变成改造形象的需求。本地预览保留历史报告已存储的原建议，重新生成报告才会应用新提示；未调用真实模型验证本轮建议质量。
