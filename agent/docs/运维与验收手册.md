# 运维与验收手册

状态：当前本地验证规范，2026-11-07建立。生产部署须有明确指令；本轮用户已授权，实际结果另见发布验收记录。本手册本身不授予发布权限。架构和当前完成情况见[技术设计](Agent架构与工程治理技术设计.md)第16节。

## 本地验证

从仓库根目录运行，使用JDK17、Maven及Python3.10以上。Windows若默认java指向其他版本，先设置JAVA_HOME到本机JDK17，并将其bin放到Path前。

```sh
python scripts/check_agent_governance.py
mvn -B -ntp -f agent/pom.xml verify
python scripts/smoke_demo.py --jar agent/target/operations-agent-0.7.0-SNAPSHOT.jar
python scripts/smoke_demo.py --jar agent/target/operations-agent-0.7.0-SNAPSHOT.jar --rule-only
python scripts/smoke_demo.py --jar agent/target/operations-agent-0.7.0-SNAPSHOT.jar --policy-snapshot
```

默认Demo使用脚本模型、内存存储，两个冒烟不产生付费模型调用。前者明确检查三路实际准备计数及Trace，后者检查显式规则回退。需要前端验证时，在front目录运行`npm run test:agent`和`npm run build`。

全量Java日志必须保留测试总数、失败、错误、跳过数。读Surefire结果确认跳过原因，不用“BUILD SUCCESS”替代执行范围。Demo中MODEL节点表示模拟模型分支，不能当作外部模型验收。

## 专用持久化环境

存储集成需要MySQL、Redis及专用测试数据库，测试有_it后缀保护。AGENT_STORAGE_IT、AGENT_MEMORY_IT等门禁按对应测试类显式开启，凭据从本机环境提供，不能写进报告。先检查测试清理范围再执行，禁止复用生产库。

必须补验：WAITING序列化与重启、结果绑定前后崩溃、终态提交失败/未知结果、重复绑定/租约争用、来源撤销、缓存重建及回滚兼容。无Docker引擎或未配置专用库时记录“未执行”，不能改测试门禁绕过数据库前提。CI中已定义MySQL/Redis服务，CI结果需实际工作流证据；本地定义不表示远端已运行。

真实模型验收需单独记录模型/provider、请求预算、调用数、超时/取消、证据正确性及费用；使用授权测试账号和隔离数据。上游不可用记录为未完成或失败，不把模拟结果替代它。

## 有效配置核验

[配置目录](配置目录.md)是源码默认值，不是服务器快照。排查前先记录构建commit、active profiles、启动时间及各运行策略的脱敏有效值。核对命令行、系统属性、环境变量、外部profile和仓库默认的覆盖来源；不要导出整份环境变量或未脱敏actuator/env。

核对各池core/max/queue和实际活动数、独立timeout、前台预算、反馈持久预算、lease/heartbeat、Trace积压及保留期。参数启动生效、没有自动热更新；writer开启后仅新Run保存前台策略，旧无snapshot记录保持LEGACY_CURRENT_POLICY。核对实际snapshot的policy hash/source，不能仅凭YAML存在断言线上生效。

## 故障定位与回滚

按runId关联正式快照、操作账本、证据和Trace；Trace是观测投影，不可据其显示成功改写正式状态。WAITING检查操作租约/结果；RUNNING重启失败检查RUNNER_LOST窗口，不自动重复执行副作用。成功提交异常先刷新正式终态，再按既有失败仲裁处理。

超时后检查真实线程是否退出及许可是否释放；模型未知usage继续计预留。Trace发送失败先检查outbox积压、重试与容量，不让出口故障阻塞模型线程。配置校验启动失败时修复非法键或恢复上一组合法配置，不静默夹取。

策略存入既有JSON投影，没有新增SQL列迁移。先部署兼容reader并确认其为回滚基线，再启用writer；v1写入后禁止退回不支持该格式的旧二进制，关闭writer不删除已有snapshot。回退保留数据库和报告对象，检查在途schema/semantics及资源引用，不自动杀任务。部署和真实验收另记版本与有效配置，本手册不充当发布证据。


## 2026-11-08 补充：业务依赖与共享网络稳定门禁

本次部署暴露了已有磁盘容量问题：Elasticsearch因flood-stage watermark将索引设为只读，业务启动批量同步索引失败并反复退出。Agent共享业务容器网络命名空间，业务重启后Agent可能继续占用旧namespace；一次Agent readiness成功不足以证明服务稳定。

切换前检查实际磁盘比例及Elasticsearch索引写保护，预留低于high watermark所需余量及本次制品/备份空间，不能只判断剩余1GiB。只能清理确认未使用的可重建镜像/JAR/上传归档，保留当前和上一版回滚制品、数据库/对象数据、备份与验收元数据；不得用修改水位阈值掩盖容量问题。

业务容器先稳定至少60秒，核对无RestartCount增长、索引写入正常和HTTP可用，再创建共享namespace的Agent。随后验证两容器`/proc/<pid>/ns/net`一致、内部依赖DNS可解析、连续readiness成功，最后打开入口并运行真实认证/模型场景。业务容器若再次重启，必须重新评估Agent共享namespace，不把Docker容器ID相同当成网络空间未变的证据。
