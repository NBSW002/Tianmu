## 本地验证

从仓库根目录运行，使用JDK17、Maven及Python3.10以上。Windows若默认java指向其他版本，先设置JAVA_HOME到本机JDK17，并将其bin放到Path前。

```sh
python scripts/check_agent_governance.py
mvn -B -ntp -f agent/pom.xml verify
python scripts/smoke_demo.py --jar agent/target/operations-agent-0.7.0-SNAPSHOT.jar
python scripts/smoke_demo.py --jar agent/target/operations-agent-0.7.0-SNAPSHOT.jar --rule-only
python scripts/smoke_demo.py --jar agent/target/operations-agent-0.7.0-SNAPSHOT.jar --policy-snapshot
```

默认Demo使用脚本模型、内存存储，两个冒烟不产生付费模型调用。前者明确检查三路实际准备计数及Trace，后者检查显式规则回退。需要前端验证时，在front目录运行`npm run test:agent`和`npm run build`。

全量Java日志必须保留测试总数、失败、错误、跳过数。读Surefire结果确认跳过原因，不用“BUILD SUCCESS”替代执行范围。Demo中MODEL节点表示模拟模型分支，不能当作外部模型验收。

真实模型验收需单独记录模型/provider、请求预算、调用数、超时/取消、证据正确性及费用；使用授权测试账号和隔离数据。上游不可用记录为未完成或失败，不把模拟结果替代它。

## 上下文压缩默认开关

源码 `agent.compaction.enabled` 默认值为 `true`（2026-11-12调整），可用 `AGENT_COMPACTION_ENABLED=false` 显式关闭。配置启动时读取，修改需重启。压缩服务及其账本/后台任务只在 `agent.storage.mode=mysql` 时装配；Demo/内存模式无需DataSource，不能视为已提供持久化压缩。开启表示允许按原触发阈值与预算安排压缩，不意味着每次请求立即压缩。生产MySQL模式仍须具备有效DataSource、迁移和模型配置。

本地回归记录：默认值与装配测试通过，AgentRuntimeTest的19项启动/运行测试通过。全量952项运行结果为1断言失败、0启动错误、121跳过；唯一Trace详情读取失败已修正内存模式的压缩派生内容保护条件，并通过TraceDetailIntegrationTest、TraceDetailsTest及架构回归。未再次执行整套952项；专用数据库集成及真实模型压缩未验收，未部署。

## 有效配置核验

[配置目录](配置目录.md)是源码默认值，不是服务器快照。排查前先记录构建commit、active profiles、启动时间及各运行策略的脱敏有效值。核对命令行、系统属性、环境变量、外部profile和仓库默认的覆盖来源；不要导出整份环境变量或未脱敏actuator/env。

核对各池core/max/queue和实际活动数、独立timeout、前台预算、反馈持久预算、lease/heartbeat、Trace积压及保留期。参数启动生效、没有自动热更新；writer开启后仅新Run保存前台策略，旧无snapshot记录保持LEGACY_CURRENT_POLICY。核对实际snapshot的policy hash/source，不能仅凭YAML存在断言线上生效。

## 故障定位与回滚

按runId关联正式快照、操作账本、证据和Trace；Trace是观测投影，不可据其显示成功改写正式状态。WAITING检查操作租约/结果；RUNNING重启失败检查RUNNER_LOST窗口，不自动重复执行副作用。成功提交异常先刷新正式终态，再按既有失败仲裁处理。

超时后检查真实线程是否退出及许可是否释放；模型未知usage继续计预留。Trace发送失败先检查outbox积压、重试与容量，不让出口故障阻塞模型线程。配置校验启动失败时修复非法键或恢复上一组合法配置，不静默夹取。

策略存入既有JSON投影，没有新增SQL列迁移。先部署兼容reader并确认其为回滚基线，再启用writer；v1写入后禁止退回不支持该格式的旧二进制，关闭writer不删除已有snapshot。回退保留数据库和报告对象，检查在途schema/semantics及资源引用，不自动杀任务。部署和真实验收另记版本与有效配置，本手册不充当发布证据。


## 2026-11-08 补充：业务依赖与共享网络稳定门禁

本次部署暴露了已有磁盘容量问题：Elasticsearch因flood-stage watermark将索引设为只读，业务启动批量同步索引失败并反复退出。Agent共享业务容器网络命名空间，业务重启后Agent可能继续占用旧namespace；一次Agent readiness成功不足以证明服务稳定。

切换前检查实际磁盘比例及Elasticsearch索引写保护，预留低于high watermark所需余量及本次制品/备份空间，不能只判断剩余1GiB。只能清理确认未使用的可重建镜像/JAR/上传归档，保留当前和上一版回滚制品、数据库/对象数据、备份与验收元数据；不得用修改水位阈值掩盖容量问题。

业务容器先稳定至少60秒，核对无RestartCount增长、索引写入正常和HTTP可用，再创建共享namespace的Agent。随后验证两容器`/proc/<pid>/ns/net`一致、内部依赖DNS可解析、连续readiness成功，最后打开入口并运行真实认证/模型场景。业务容器若再次重启，必须重新评估Agent共享namespace，不把Docker容器ID相同当成网络空间未变的证据。

## 2026-11-08：材料并行、私有正文和向量来源

本节是发布前门禁，不代表已经部署。

1. 排空在途Run和反馈job，核对Skill 5.1.0与新制品。`AGENT_TOOLS_PARALLEL_ENABLED`默认true；有效false会让同批工具串行。运行只允许受限提交返回本工具、当前Run、冻结请求及既有deadline对应的Pending；原生调用全部配对后才能挂起。准备调度仅扫描本实例活跃RUNNING；前置识别尚无task时跳过。持久RUNNING崩溃仍按RUNNER_LOST处理，不新增重放。
2. 使用 `python scripts/milvus_feedback_schema.py --collection feedback_qwen37_2560_origin_v2 --dimension 2560 --with-provenance` 生成新集合申请。该命令只输出JSON；须实际创建、加载并验证维度/权限，再把collection切到独立新集合、开启 `AGENT_FEEDBACK_MILVUS_PROVENANCE_ENABLED=true`。所有写者包括预热、后台报告必须统一切换，旧实例不能访问新集合。旧集合保留供回滚；不自动删除或混用模型。新集合起初为空，发送后异步预热和报告缺失补算逐步填充。未迁移时兼容旧集合，来源只显示UNKNOWN，不能声称已完成来源迁移。
3. 新快照保留脱敏正文并标记SOURCE_GUARDED。输入、输出、错误、提示词、思考、代码、执行结果及截断预览均要求详情端点的实时来源校验。授权有效可读；撤销或来源authority缺失拒绝读取。旧SOURCE_PROTECTED占位记录没有原文可恢复，不补造。
4. MinIO记录GET/PUT/DELETE、耗时、失败类别和HTTP状态，不记录端点、对象key或SDK错误原文。受控结果写入使用同key和digest校验未知提交，仅404允许最多一次同key重写；第二次未知提交只读验证，不再写。生产connect创建的每个HTTP Call按剩余deadline与5秒上限设置timeout，注册原取消信号；无CallControl的既有读写没有增加自动重试。403/完整性错误为不可重试ARTIFACT_UNAVAILABLE。构造器直接传入自定义SDK client时，HTTP超时/取消由调用者的client配置负责。
5. 四种真实场景分别验收：新集合首次生成；新反馈落库后预热命中；报告语义结果缓存复用；显式强制重新分析。强制重新分析不等于忽略有效向量缓存。记录Run/Trace、制品commit、有效配置、来源计数及实际模型调用；网页/下载报告只检验业务输出，不向用户直出内部诊断。

Trace验收应看到：视频与材料准备的实际时间重叠；来源整理各自依赖同一快照；联合聚类依赖已接受的来源；准备交付同时依赖MATERIALS接受Span和当前Run原生批次已配对的调用。不同Run或不同native group不得串线；缺关联时不靠时间补箭头。视频失败、取消、材料完成后父Run失败均不得交付报告；终态后现有孤儿回收取消job并结清准备账本。

## 收尾对象瞬断修复（2026-11-08）

真实视频报告在无模型work的finishLevel阶段遇对象传输异常会直接失败。现在同一次advance内按既有maxAttempts最多三次恢复确定性收尾，每次重读权威job、重新授权，沿用原deadline及取消信号；已完成模型work不重算。MERGE输入及Asset写入使用受控同key恢复。后台收尾所属聊天Run通常为WAITING_OPERATION，重启后可恢复；三次为每次advance的限额，跨重启总边界仍为原job.deadline，未引入持久总次数。权威提交前再次校验权限、取消及deadline。TraceDetails自身对象IO不再覆盖业务存储诊断。定向四类测试及verify通过，含注入收尾读取瞬断后不增加模型调用的用例；发布后仍须真实验收。
