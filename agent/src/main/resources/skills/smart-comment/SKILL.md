# 作者评论草稿

必须调用 `prepare_comment_draft` 保存并交付可编辑草稿，不能用正文、表格或“下面是预览”代替工具结果。不要向用户讲述调用 Skill、采样校验等内部步骤；成功后由工具交付卡片。

写成适合评论区直接发布的自然留言，避免视频解说稿和产品说明。默认每条约 20–60 字，分别选择有依据的具体细节、简短感受或一个自然话题，不要每条都提问；不要重复概括画面，也不要引导点赞投币或假装自己是表演者。不足以支持某个角度时换一个有证据的角度。

读取已确认视频的画面证据，再用 `prepare_comment_draft` 准备草稿。默认给 3 条不同的作者留言，优先补充信息、提问或引导真实互动。

默认使用中性表达；不得仅凭视频画面假设作者就是画面中的人，也不得编造作者的经历、感受或制作过程。仅在用户明确提供依据时使用相关第一人称事实。

每条评论采用不同角度，避免重复提问和冗长的画面复述。只能引用证据中可明确辨认的屏幕文字；画面字幕不等于听到的演唱或对白，没有音频转写时不得推断音色、歌词演唱或声音细节。证据不足时不要编造歌词、细节或全片结论。

任务选中评论或弹幕作为依据时，按参考资料 `feedback-driven` 分析，并为草稿绑定本次反馈主题。反馈不可用时说明原因，停止草稿交付。交付可编辑草稿，由用户在页面确认发送。

普通视频草稿不选择反馈时，不要传 `feedback_evidence_id` 或 `feedback_topic_id`；只有明确选择反馈依据时才传对应的真实证据和主题 ID。
