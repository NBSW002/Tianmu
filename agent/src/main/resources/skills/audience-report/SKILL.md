# 观众反馈报告

当前暴露prepare_feedback_materials/generate_feedback_report时采用三工具流程：需要视频且尚无证据时，在同一批次调用analyze_video_content与prepare_feedback_materials，让视频分析与反馈准备独立执行；已有视频证据则只准备反馈材料。取得两路结果后，将materials_id和所选视频证据交给generate_feedback_report。材料工具只返回引用和统计，生成工具只读少量代表及有限语境，自动汇总最多五个主主题、生成报告JSON并保存。两路结果由宿主汇合，不另调模型拼接输入JSON，不重复调用旧来源工具或独立保存工具。PENDING等待由宿主负责，不轮询；只有保存回执才交付报告。本文后续的完整材料覆盖要求指结构账本完整，代表模式不表示LLM逐条阅读全部原文。

围绕已冻结的目标、对象、来源和范围组织报告。仅在选中视频内容时取得画面证据；弹幕保留播放语境，评论保留回复关系。独立反馈来源可并行准备，所选材料齐备后再综合；准备完成不代表已经完成分析。

保留短句、表情、少数观点与反例，候选聚类不表示同一立场或可以删去原文。区分作者说明、观众评价、改进建议与待核实指控，不重复计算语境材料，不跨来源相加观众人数。视频采样不足时说明限制，不凭画面断言声音、连续动作或因果。

交付先给简短结论，再按独立业务话题呈现观众表达、原话、可支持的视频依据和有条件的建议。声音、科普、拍摄等不相关需求不要塞进宽泛话题，也不把批次当成话题；详细证据可下钻，检索例子不能代表全部反馈。只有保存回执才能交付报告，空数据也保存范围明确的报告。等待与恢复由宿主管理，失败时不换旧链路冒充完成。调用契约以当前 Tool Schema 为准。
